\# .trae/rules/home\_rule.md



\## 核心原则：最小上下文、指定文件、不瞎搜



\### 文件操作

\- 改代码前，用户会明确指定要改的文件路径

\- 不要主动全局搜索整个 lib/ 目录

\- 不要 Read 与当前任务无关的文件

\- 一次任务最多 Read 3-5 个文件，超了先停下来问用户



\### 搜索

\- 除非用户明确要求，否则不执行 grep/find 全库搜索

\- 需要定位代码时，让用户告诉你文件名或目录



\### 终端输出

\- 执行 flutter run / dart analyze 后，只关注错误行

\- 不要把完整终端输出贴回上下文

\- 有报错只贴报错部分（5-10行），不要贴整段日志



\### 对话

\- 一个提示词只做一件事，不要混合多个不相关的改动

\- 大功能（如首页重构）单独开新对话，不要和之前的任务堆在一起

\- 用户说"老规矩"时，只做 git 操作，不读代码不分析



\### 模型选择

\- 改文案/改颜色/加图标/简单UI调整 → 用快模型

\- 跨文件联动/架构设计/联调 → 用强模型

\- 不确定时问用户



\### 代码风格

\- 样式全用现有 scheme token，不新造

\- 不侵入已有 models/解析逻辑

\- 复用现有组件，不新写一套

\- 改完 dart analyze lib → flutter run → 通知用户验证
